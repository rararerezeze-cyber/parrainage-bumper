# AutoFresh final production closure — 2026-09-11

Status: **FINISHED_WITH_KNOWN_LIMITATIONS**.

This document closes the engineering phase for the currently supported AutoFresh
scope. It does not claim that external platform restrictions have disappeared and
it does not weaken any write-safety gate.

## What is now final

### Slack/cloud control

Slack is the primary production operator path. The Cloudflare Worker verifies
Slack signatures and the user allow-list, deduplicates retries/double-clicks, and
dispatches the historical `hermes_operator.yml` backend. Normal operation does
not require the operator PC or Hermes.

Production command, Super-Parrain and monitor workflows now run with
`AUTOFRESH_PHASE=PRODUCTION`.

### Code-Parrainage + Parrainage.co bumper

The actual site timing remains exactly five persisted random UTC slots/day.

Cloudflare Cron at `3,18,33,48 * * * *` is the sole routine scheduler wake-up.
The duplicate native GitHub cron was removed. A poll with no due random slot does
not visit either platform.

The partial-cycle defect found on 2026-09-11 is closed:

- site outcomes are durable per logical slot;
- a site already proven successful is never replayed for that slot;
- only a failure proven to happen before any site action can be marked retryable;
- an ambiguous/post-action failure is never automatically replayed;
- safe recovery is bounded to one delayed dispatch.

Live evidence:
- run `34607923542`: Code-Parrainage and Parrainage.co both succeeded;
- run `34629797313`: Code-Parrainage and Parrainage.co both succeeded.

The earlier same-day partial runs are retained truthfully in the ledger as
Parrainage.co-only successes. They are not rewritten as complete cycles.

This also proves the current Code-Parrainage slider handling in production: the
changed client-side success signal is tolerated, normal login submission remains
authoritative, and the real `Actualiser` action succeeded.

### Super-Parrain

Super-Parrain keeps its independent `FUSED_UPDATE_BUMP` ownership with a 24-hour
minimum plus persistent random delay. It is not coupled to the five-slot bumper
and was not redesigned during this closure.

### ReferralCode.tv

The scheduled workflow was deliberately removed. GitHub-hosted Chromium is
deterministically stopped before login by a standalone Cloudflare Turnstile
challenge. Repeating that known blocker several times per day provided no
production value.

`bump_referralcode_tv.yml` remains manual-only via `workflow_dispatch` so an
operator can explicitly re-test if the external gate changes. Content saving
remains human-only because the site requires CAPTCHA. No bypass is implemented.

### Monitor

The public-offer monitor remains observation-only with
`monitor_auto_accept=false`. Known anti-bot responses are classified as external
blockers and are not worked around.

- ReferralCode.tv — `WRITE_VERIFIED` capability proof, but
  `HUMAN_SAVE_REQUIRED` and bumper manual-only under the current Turnstile gate.
- ReferralDrop — `AUTH_BLOCKED_MANUAL`.

## External limitations, not open engineering tasks

1. ReferralCode.tv CAPTCHA/Turnstile restrictions.
2. ReferralCodes lacks a proven documented safe update route for unattended
   mutation.
3. ReferralDrop lacks a supported unattended authentication/write route.
4. Some monitor sources return anti-bot responses.
5. 1Parrainage may enforce a daily edit quota.
6. Super-Parrain's already-authenticated-session retry branch has not needed a
   natural live exercise.

## Deferred natural evidence

A future genuine public offer change may produce another end-to-end sample:
monitor → Slack → explicit confirmation → compatible writer → backup → reread →
post-verification.

That event must **not** be manufactured just to create proof. All component safety
paths are already covered independently; this future sample is operational
evidence, not a release blocker.

## Non-negotiable safety invariants

- no CAPTCHA or Turnstile bypass;
- no speculative ReferralCodes Commit;
- no synthetic live mutation for test cosmetics;
- no automatic replay after an ambiguous site action;
- no duplicate GitHub cron for the randomized bumper scheduler;
- no scheduled ReferralCode.tv retry while the known external gate is unchanged;
- monitor stays observation-only unless explicitly redesigned;
- Slack writes still require the signed confirmation path and backend safety
  gates;
- post-write reread and verification remain mandatory.
